Qué vas a lograr

Al terminar los tres días vas a poder:

  • Reconstruir y explicar el mapa de módulos del año, con sus programas, herramientas e instrumentos.
  • Publicar un sitio web en GitHub Pages usando Git: clonar, hacer commits, subir cambios y etiquetar versiones.
  • Programar interactividad en JavaScript: pintar contenido desde datos, filtrar, guardar progreso y evaluar con un quiz.
  • Trabajar en equipo con control de versiones y revisar el trabajo de otras personas.
  • Explicar con tus palabras lo que aprendiste y demostrarlo en vivo.

Cómo está pensada esta guía

Repasar no es releer: es recordar, explicar y crear. Por eso el repaso se convierte en un producto real.

Recordar antes de releer

Cada día empieza intentando recordar sin apuntes. Lo que no te sale es lo que más necesitas repasar.

Aprender enseñando

Cada ficha se escribe para que un compañero pueda repasar el módulo con ella. Si puedes explicarlo, lo sabes.

Evidencia sobre promesa

Todo avance queda en GitHub: commits, versiones etiquetadas y una URL pública que cualquiera puede abrir.

Pensar sobre cómo piensas

La bitácora diaria te obliga a decir qué aprendiste, qué te costó y cómo lo resolviste.

La IA es tu tutor, no tu atajo

Puedes usarla en cada paso. Registras tus prompts y tienes que poder explicar el código: en la feria se te pregunta.

Equipo con responsabilidad individual

Cada integrante es dueño de sus módulos y sus commits llevan su nombre. El equipo gana si todos aprenden.

El producto: tu HUB 3DS·B

Un portal educativo estático (HTML, CSS y JavaScript, sin frameworks) publicado en GitHub Pages. Es el lugar al que cualquier compañero puede entrar para repasar un módulo: qué se hizo, con qué programas y herramientas, qué instrumentos se usaron y dónde seguir aprendiendo. Debe ser creativo, intuitivo, dinámico e interactivo.

Qué les damos

La idea de cada misión, preguntas para pensar, posibles herramientas y recursos confiables para investigar.

Qué no les damos

Código, comandos ni prompts listos. Investigar, equivocarse, preguntar y corregir también es repasar: el portal es de ustedes.

Si algo falla: pistas, no soluciones

Antes de levantar la mano, revisa estas pistas. Dicen dónde mirar; encontrar la solución es parte del repaso.

Mi página en GitHub Pages dice 404

Revisa el nombre exacto del archivo de inicio y dónde está dentro del repositorio, que Pages esté activado en la configuración del repositorio (¿de qué rama y de qué carpeta publica?) y espera un par de minutos. Abre la URL en una ventana de incógnito. Documentación de GitHub Pages.

Se ve sin estilos o no cargan los scripts

GitHub Pages distingue mayúsculas de minúsculas y las rutas dependen de dónde se publica el sitio. Compara cómo escribes cada ruta con dónde está realmente el archivo. Abre las herramientas de desarrollo (F12) y mira la pestaña Consola y la pestaña Red: ahí dice qué archivo no se encontró.

Git rechaza mi envío (rejected)

Alguien subió cambios antes que tú. Piensa qué necesitas hacer con los cambios de los demás antes de subir los tuyos. Busca «pull» y «rebase» en Pro Git.

Conflicto al unir cambios

Git marca en el archivo las dos versiones en conflicto. Decidan en equipo cuál se queda (o combinen ambas), borren las marcas y continúen. Si dos personas editan siempre el mismo archivo, revisen cómo repartieron el trabajo.

Se fue el internet

Piensa qué partes de Git necesitan conexión y cuáles no. Sigue trabajando en local, guarda copia de la carpeta del proyecto en una memoria USB al final de cada día y sube todo cuando regrese la conexión.

Live Server no abre mi página

Hay más de una forma de levantar un servidor local: busca en la documentación de tu lenguaje favorito (Python, PHP o Node) cómo servir una carpeta.

«git no se reconoce» o «not a git repository»

Si dice que no se reconoce, revisa si Git está instalado y si la terminal se abrió después de instalarlo. Si dice «not a git repository», pregúntate en qué carpeta estás parado.

Subí una contraseña o una clave por error

Cámbiala de inmediato en el servicio al que pertenece: borrar el archivo no basta, porque queda en el historial del repositorio. Avisa al docente.
